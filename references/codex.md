# Optional Dot/Codex session adapter

Read this only when operating through Dot/Codex with native session tools. The Markdown project records remain the primary handoff on every agent.

For a new project, the requested Dot/Codex workflow includes an accompanying project session. Inspect available projects/environments and use their returned identities. If the current session was already created for this project, record and reuse it. Otherwise create the session through supported tools within their authorization requirements; when a tool requires an explicit session request that is absent, ask for that missing authorization with the prepared assignment. The assignment links the project records, milestone, acceptance checks, scope, and authorization limits. Avoid including credentials or unrelated vault content. Record the returned session reference after confirmed creation.

For an existing project, inspect its recorded session and latest outcome. Reuse it when it still owns the requested work. Check for an already-created or pending session before retrying an uncertain creation; a fresh chat, renamed folder, or inaccessible link does not authorize a duplicate. Do not move work to a different environment or replace the selected session to bypass unavailable access. Prepare a portable handoff and state the missing capability instead.

Send implementation/fix assignments through a supported continuation tool only within the user's authorization for that task. Creating a project session does not grant permission to message unrelated tasks or people. Use the existing selected thread for repairs; read its actual outcome before issuing another assignment.

If session tools are absent, other agents can implement directly or use their own authorized coordination tools. When Dot/Codex cannot fulfill required session creation, report that adapter limitation and preserve the prepared assignment. Do not claim that a session exists, monitoring will continue, or the work was transferred without confirmation.

On a handoff, supply a short resume message pointing at the records. Never rely on conversation history, a session URL, or executor-specific tools as the only location for project facts or verification evidence.
